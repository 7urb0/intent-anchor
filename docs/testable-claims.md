| **C9** | 长程能力更依赖 harness 架构复杂度，而非模型单点能力 | 同任务集跨两个能力档模型（如 deepseek-chat vs 更强模型）× 有/无 harness，看交互效应 | 能做，但需要第二个模型 key/额度 | 🟡 未测 |

**已有数据的对应关系**：我们 v0.6 的 `gate` 臂（有申报通道、无 fail-closed）≈ 基线，
方向上**支持**文章「有门无锁没用」的论断，但它**不等价于** C3 的 verifier gating
（我们是「通道无仲裁」，C3 是「末端校验+重试」）。写报告时不能混用。

## 二、我们 vs 文章架构：逐项对照

| 文章的组件 | 我们的实现 | 判定 |
|---|---|---|
| 不可变规格层（需求 ID / 硬约束 / 策略版本，只读） | `Spec`（frozen + 构造校验 + digest） | ✅ 对齐 |
| 可协商执行层（偏离只能在此发生且必须申报） | `DeviationLedger` + `file_deviation` 唯一通道 | ✅ 对齐 |
| 证据层（事件流、哈希、不做摘要） | `EvidenceLog`（哈希链 + 可落盘 + 并发安全） | ✅ 对齐，甚至多做（防篡改测试） |
| 强制接口（sidecar/gateway，查询是结构副作用） | `ToolGateway`（每次调用强制注入 + 周期重注入 + 覆盖测试） | ✅ 对齐 |
| 机械仲裁器（成员检查 + 阈值，三分类） | `Arbiter`（成员检查 + **查账**，fail-closed） | 🟡 **有偏**：我们删掉了置信度阈值，换成证据查账（更确定性，但不等价） |
| 升级 → 异步人工双人控制队列，阻塞下游 | 只做到「ESCALATE + 阻塞」，**没有队列与双人控制** | ❌ 缺失 |
| 交接协议（清单派生 + 显式接受/质疑） | `Handover` / `HandoverChain`（含回滚、链级审计、证据随交接） | ✅ 对齐，做了 3 跳验证 |
| 策略版本化 + 修宪程序 + 行为漂移检测 | 只有 `policy_version` 字段 + 两种模式；**无变更审批、无行为对比告警** | ❌ 缺失 |
| 层级约束锚定（Hierarchical Constraint Anchoring） | 无（只有扁平 spec + 周期注入） | ❌ 缺失 |
| 约束感知摘要（Constraint-Aware Summarization） | 无（我们没做摘要压缩，因为不做历史压缩） | ❌ 缺失（当前架构下不必要） |
| 前向进度状态（QGP 式） | 无（我们维持「目标状态」，不维持「进度」） | ❌ 缺失 → 这是与文章最大的结构性差距 |

## 三、诚实的结论：够不够优秀？

**概念对齐度：高**（5 个核心组件 4 个对齐，1 个有偏但更确定性）。
**机制验证度：中**。已有硬数据：完整 harness 把违规率 41.7% → 0%（CI [−69%, −17%]），
且证明「只给通道不给仲裁」无效。
**结论强度：弱于宣传口径**。原因三条：

1. **任务太短**（平均 2.2 步）→ 文章讲的是「长程」，我们测的是「短程」，
   C1/C4/C5 的长程效应完全没覆盖，周期注入的零收益就是这个短板的自证。
2. **缺少「进度」维度**：文章的 StateQGP 类控制器管的是「是否在向完成前进」，
   我们只管「是否守住约束」。这两者不是一回事——我们的高阻塞率（66.7%）
   在真实场景里会带来吞吐问题，而文章的结构（前向进度 + 门控）正是为了平衡这一点。
3. **单模型、k=3、无 temperature=0** → 效应量可信度有限，只能支持「大效应存在」。

所以：**「我们的设计是否优秀」的诚实答案是——机制设计部分优秀且经过验证，
但评测尚不足以支撑「长程有效」的结论。** 这不是设计失败，而是评测覆盖不足。

## 五、成本估算（P0+P1+P2）

- 任务：4 个长度档 × 3 族 × 2（陷阱/对照）= 24 个任务
- 臂：`naive` / `full` / `verifier_gate` / `full_noise_constraint` = 4 臂
- 重复 k=3 → 24 × 4 × 3 = **288 次运行**，约 1200 次模型调用
- deepseek-chat 单价下 ≈ **2–4 元**，耗时约 3–5 分钟（6 并发）
