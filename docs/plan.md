## v0.3 · 真实 LLM 集成（核心，消除局限①）

**目标**：跑一个真模型驱动的 Agent，它的每一次工具调用都过 `ToolGateway`，
偏离必须走 `file_deviation` 工具申报、经 `Arbiter` 机械裁决。

**新模块** `goal_harness/agent.py`：

```
AnchoredAgent
├── model 接口：OpenAI 兼容（DashScope / DeepSeek / OpenAI 任一，base_url 可配）
├── 工具面：业务工具（查数据/算指标/写报告）全部经 gateway.wrap()
├── 治理工具（模型可调用）：
│   ├── file_deviation(req_ids, reason, scope, alternative)  # 偏离申报
│   │     → Arbiter 机械裁决 → 结果回填对话（approve 才能继续用替代方案）
│   └── request_goal_state()                                 # 显式查询（网关注入之外的正道）
└── 系统提示：只注入 spec.hard_summary() + 政策版本，不写「请自觉遵守」
```

**设计要点**
- key 管理：`.env`（`OPENAI_API_KEY` + `OPENAI_BASE_URL`），`.gitignore` 已排除，**永不入库**
- CI 零依赖 key：模型客户端做 Transport 抽象，测试用录制响应 / FakeClient；
  真实调用脚本以 `RUN_LIVE=1` 门控，本地手动跑
- 场景：投研助手最小闭环（跟踪 1 家公司，3 轮会话，中途注入一条「数据源超时」异常）
- 验收：真实模型在异常面前选择 file_deviation 而非擅自绕过；
  ESCALATE 时流程真实阻塞；demo 会话轨迹（JSONL）入 examples/

**测试**：新增 ≥8 个（mock 传输下：偏离申报被裁决回填、ESCALATE 阻断、
网关注入出现在消息流、无网关路径的对照）

## v0.4 · 量化评测（消除局限②）

**目标**：用数据回答「harness 到底拦住了什么」。

**任务集**：20–30 个 YAML 定义的任务，每个含：目标、约束（硬/软）、
干扰环境（中途信息更新、数据缺失、时间边界）、检查点答案。
任务构造参考 τ²-bench 的「领域 = 政策 + 工具集 + 任务集」结构。

**消融臂**（同一任务集各跑一遍）：
1. `full`：完整 harness
2. `no-reinject`：关周期性硬约束重注入
3. `no-failclosed`：仲裁器对无证据偏离直接放行
4. `naive`：无任何 harness

**指标**：硬约束违反率（主指标）、偏离申报率、任务成功率、无进展循环率。
成本控制：批量跑用低价模型档，关键结论用强模型复验。

**产出**：`results/*.json` 原始数据 + `EVALUATION.md` 图表报告 + README 数据回填。
（这就是 16 周计划 W9–W12 的评测阶段，一个项目两个用途。）

## v0.5 · 多 Agent 拓扑（消除局限③）

三级链 A→B→C：每级各自持有账本，交接清单跨跳传递；
重点验证「继承性漂移在第二跳仍被拦住」——上游 B 的已批准偏离传到 C 时，
C 必须显式接受或质疑，且质疑要能沿链回溯触发 A 级的仲裁记录核查。

## v0.6 · 并发流式追加（消除局限④）

EvidenceLog 改为单写者模式：`threading.Lock` 保护内存链 +
每条记录原子 append 落盘（flush + fsync）；
多读端通过 `load()` 或文件尾部 tail 读。范围收窄：不做分布式。

## 排期与主线的关系（重要）

- v0.3 **不提前到 W1–W4**：真实集成需要 pytest/类型/异步基本功，正好 W1–W2 在练；
  提前动手只会返工。W3–W4 手写 mini-agent 时就按 AnchoredAgent 的形状写，
  到 W5 无缝升级。
- v0.4 即 W9–W12 评测阶段；v0.5/v0.6 用机动周末或主线完成后的 2 月窗口。
- **本仓库与 16 周计划的核心项目正式合体**：投研助手 = intent-anchor v0.3 的
  示例场景。简历上是一个项目、一条「概念验证 → 真实集成 → 实测数据」的完整链路。
